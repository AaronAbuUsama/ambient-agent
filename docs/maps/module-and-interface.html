Ambient architecture · target boundary

Small interfaces, one owner for each durable transition.

Every mapped boundary is realized: one composition root, one Conversation service over one aggregate-shaped work store, a deep model runtime, the validated configuration document, the shared proof harness, and the WhatsApp service facade.

01 · Target dependency graph

Call inward through domain ports

The composition root constructs adapters. Conversation owns the run protocol. Pi, Drizzle, libSQL, environment access, and whatsappd types stop outside role contracts.

02 · Boundary rules

What each interface hides

A boundary earns its existence by absorbing complexity. The target avoids a public repository bag, generic WhatsApp command executor, or universal Agent superclass.

Conversation owns the run

  • One work store claims, renews, completes, fails, releases, and recovers.
  • The role agent sees curated input and granted tools, never repositories.
  • Terminal model text is private; only retained effects prove communication.

WhatsApp owns the habitat

  • Host lifecycle, accepted ingress, mirror, history, and durable operations stay inside.
  • Conversation gets a destination-bound subset such as text or reactions.
  • whatsappd operation types are adapted, not duplicated.

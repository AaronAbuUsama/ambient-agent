Ambient · current system map

One colleague, several specialized forms of agency.

Ambient lives in WhatsApp, maintains one Root-led identity, and acts through durable Conversation, Worker, and Memory instances. The current build focus is not another product phase. It is rescuing the architecture without losing the behaviour already proven.

Active slice · Conversation service + work store

01 · Product architecture

How Ambient coheres

The Root owns identity, attention, commitments, synthesis, and delegation. It normally speaks through durable Conversation Agents rather than bypassing them. Workers perform bounded objectives; Memory Agents maintain evidence-backed continuity. Durable assignments and reports keep every handoff visible.

Cohesion

One identity, not a society

Specialized instances are forms of Ambient's agency. The Root supplies continuity; durable protocols keep responsibility visible.

Conversation

Private thought, explicit speech

Terminal responses are private reports. Only successful conversation-tool outcomes prove that Ambient spoke or reacted.

Autonomy

Durable reasons to wake

Messages, results, deadlines, failures, and commitments can re-enter the Root loop. Waiting and deliberate inaction remain valid decisions.

02 · Delivery practice

Build by evidence

Product principles are stable; mechanisms are discovered locally. Only one active vertical slice is planned in detail. Each proof ends with a review before the next slice is selected. Patterns become shared architecture only after real slices prove that they are shared.

01 · FRAME

One product question

Name the concrete journey, owner, durable protocol, non-goals, and proof gate.

02 · INSPECT

Protect invariants

Read the current code, retained state, and proofs before changing the mechanism.

03 · BUILD

One vertical path

Complete the smallest real journey. Do not scaffold distant roles or policies.

04 · PROVE

Retain evidence

Test restart, retry, deduplication, failure, and any real external effect.

05 · REVIEW

Simplify the model

Check module depth, duplicate policy, accidental complexity, and new evidence.

06 · SELECT

Choose what is next

Update the ledger. Detail one active slice; keep future themes unordered.

Review feeds the next framing decision · no frozen master plan

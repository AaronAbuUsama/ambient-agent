Ambient architecture · durable protocols

Callbacks wake the system. Retained records carry responsibility.

WhatsApp ingress and Conversation execution are separate protocols joined by a durable Inbox item. Claims, tool calls, operation receipts, and terminal results remain inspectable across process or model failure.

01 · Accepted WhatsApp input

Commit before wake

The accepted-source sequence, native identity, Observation, Inbox item, and cursor form one transaction boundary. The post-commit wake is only an optimization.

02 · Conversation run

Claim, act, retain, complete

The work store creates and fences the run. Every model tool call is retained before the effect. A WhatsApp operation receipt survives a later model failure.

03 · Memory digestion

Evidence in, validated ontology out

History is imported as evidence only — it never creates Inbox work and never wakes a speaker. A durable Memory Job carries one bounded window; the Memory Agent proposes, the host validates and applies, and the terminal transition commits job, run, and evaluation signal together.

04 · Protocol invariants

What restart must not change

Timers, callbacks, and live model sessions can disappear. These retained identities and transitions prevent loss or duplication.

Ingress authority

  • Source sequence advances with Observation and Inbox retention.
  • Native WhatsApp identity deduplicates replayed accepted input.
  • Conversation reconciliation finds committed Inbox work after a lost wake.

Run authority

  • Claim membership and lease ownership fence every terminal transition.
  • Tool starts and outcomes remain attached to one run and call identity.
  • WhatsApp idempotency derives from retained run work, not model text.

Memory authority

  • One current claim per entity and predicate: restatements reinforce, changes supersede.
  • A chat id is never an identity; linkable ids must be evidenced in the batch.
  • Patches apply idempotently per job; the judge sees the full digested window.

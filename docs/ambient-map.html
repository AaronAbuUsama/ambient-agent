Ambient · system and delivery roadmap

From durable spine to a working conversational agent.

The backend foundation is complete. The next cut connects real WhatsApp events to durable Ambient records. The cut after that turns those retained records into bounded, inspectable Conversation runs.

Current position: Phase 1 complete

01 · Delivery sequence

Where we are

Phase 0 removed the abandoned terminal product. Phase 1 built the durable authority. Phase 2 is intentionally split into two proof-sized cuts: first ingestion, then Conversation.

Built and proven

Durable authority exists

  • Authenticated WhatsApp state and full local-history backfill
  • Node + pnpm runtime and Drizzle-managed libSQL schema
  • Observations, inbox, runs, tools, tasks, evaluations, and memory records
  • Restart, uniqueness, lease, transition, and lineage invariant tests

Next cut

Make one message durable

  • Translate a native WhatsApp message into an Observation
  • Atomically create its Conversation Inbox item
  • Replay safely without duplicates
  • Prove with controlled and opt-in live ingestion

Not built yet

No model behavior is live

  • No Conversation Agent or outbound reply
  • No Worker execution or task report-back
  • No episode construction or Memory Analyst
  • No live account end-to-end journey proof

02 · Product architecture

The whole system

Agents never call each other directly. The Ambient database is the protocol: accepted messages, run inputs, tool effects, tasks, results, memory patches, and evaluations are all durable before the next role acts.

03 · Next cutover

What we prove next

Do not introduce the model and live reply path in the same cut as ingestion. First prove accepted channel input becomes durable exactly once. Then prove deterministic scheduling and scoped Conversation behavior over that retained input.

Exit gate · Cut 2A

Exactly-once channel ingestion

  1. A controlled native message produces one Observation and one Inbox item.
  2. Concurrent delivery and replay retain the same native identity once.
  3. A process restart preserves the pending item.
  4. An opt-in live account proof retains a real message without sending anything.

Exit gate · Cut 2B

Bounded Conversation behavior

  1. One retained message creates one Conversation run.
  2. Rapid messages coalesce; arrivals during the run remain pending.
  3. The run either sends through its bound chat or records deliberate silence.
  4. Restart never consumes an item twice or targets another conversation.

04 · Completion definition

What “Ambient works” means

The product is complete only when the whole loop survives process boundaries. A model response alone is not completion; accepted work and effects must remain inspectable and replay-safe.

Conversation

Durable front door

  • Inbound messages retained exactly once
  • Reply, recall, start work, and query work
  • Scoped effects cannot cross conversations

Work + memory

Durable continuation

  • Worker completes tasks exactly once
  • Results return to the originating conversation
  • Corrections supersede Claims with Evidence

Operations

Inspectable and restart-safe

  • Runs, tools, transitions, and evaluations are retained
  • Every accepted boundary survives restart
  • Configuration changes are regression-gated
